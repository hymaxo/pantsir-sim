# Pantsir SX Simulator

**Русский** | [English](README.en.md)

Прототип симулятора рабочего места расчёта ЗРПК на Godot 4. Проект моделирует обнаружение и сопровождение воздушных целей, переключение между командирским и операторским экранами, наведение, пуск управляемых ракет и стрельбу из пушек.

Текущая версия проекта: `1.1.0`.

> Проект является игровой/исследовательской симуляцией. Параметры и поведение систем условны и не претендуют на достоверное воспроизведение реального комплекса.

## Скачать

Готовые сборки для Windows и Linux лежат на странице [Releases](https://github.com/hymaxo/pantsir-sim/releases). Распакуйте архив и запустите `PantsirSim.exe` (Windows) или `PantsirSim.sh` / `PantsirSim.x86_64` (Linux). Исполняемый файл и `.pck` должны лежать в одной папке.

## Возможности

- главное меню с выбором комплекса (Панцирь-С1, Панцирь-СМ; СМ-СВ — в разработке) и настройками окна;
- обзорная РЛС (СОЦ) с вращающимся лучом, ошибками измерений, радиальной скоростью, клаттером и дальностью обнаружения по закону R⁴ от ЭПР цели;
- у С1 — один луч СОЦ (60 об/мин) и секторный обзор по углу места: число секторов радар выбирает сам по верхней границе и дальности ЗУР; у СМ — два луча спина к спине (30 об/мин) без секторов;
- меню СПЗ «Ручная настройка»: ограничение по скорости, нижняя граница по высоте и углу, порог ЭПР (настройки сохраняются между запусками);
- МРЛС с допоиском (3 из 5 обнаружений) и автосопровождением (ДПЦ → АС);
- командирский экран с радиолокационной обстановкой и формуляром целей;
- операторский экран с тепловизионным визиром, зоной поражения и каналами наведения;
- 6DOF-модель ракеты с командным наведением (П-РЛ → ЦУ) по данным War Thunder: 95Я6 у С1 (20 км), у СМ — 95Я6М (40 км, 1700 м/с, без взрывателя: подрыв по команде комплекса, направленный осколочный поток вперёд) и малогабаритная ТКБ-1055 (7 км, по 4 в контейнере вместо одной 95Я6М);
- выбор ЗУР для следующего пуска — кнопка под «Запросить перезарядку»;
- пушки с расчётом упреждения и автоматический режим огня (АО / АВТ-П);
- запрос перезарядки: выбор боекомплекта по трубам и пушкам (у СМ в трубу ставится 95Я6М или контейнер 4× ТКБ-1055), 30 с без стрельбы;
- процедурный рельеф 80×80 км с лесом, ослабляющим радиосигнал;
- цели: БПЛА, крылатая ракета с огибанием рельефа, залп РСЗО;
- экспорт для Linux и Windows, автосборка релизов через GitHub Actions.

## Требования

- Godot Engine `4.7` — эта версия указана в `project.godot`;
- рендерер Forward Plus;
- для сборки исполняемых файлов — установленные export templates соответствующей версии Godot.

Совместимость с другими версиями Godot 4 отдельно не проверялась.

## Быстрый запуск

### Через редактор

1. Откройте Godot Project Manager.
2. Нажмите **Import** и выберите `project.godot` из корня проекта.
3. Дождитесь завершения импорта ресурсов.
4. Запустите проект клавишей **F5** или кнопкой **Run Project**.

Главная сцена уже настроена: `res://Scenes/MainMenu.tscn`. Бой — `res://Scenes/main_system.tscn`, выход из боя в меню — `Esc`.

### Из командной строки

Если исполняемый файл Godot доступен в `PATH`:

```bash
godot --editor --path .
```

Запуск проекта без открытия редактора:

```bash
godot --path .
```


## Управление и сценарий работы

| Действие | Управление |
|---|---|
| Переключить командирский/операторский экран | `C` или `С` |
| Огонь выбранным оружием | `Space` |
| Уменьшить масштаб/увеличить отображаемую дальность | `-` |
| Увеличить масштаб/уменьшить отображаемую дальность | `+` или `=` |
| Выбрать трассу | ЛКМ по строке таблицы на командирском экране |
| Прокрутить таблицу трасс | Колесо мыши над таблицей |
| Включить питание, обзорную РЛС или секторное сопровождение | Экранные/панельные кнопки |
| Выбрать ракеты или пушки | Кнопки `ЗУР` / `ПШК` на экране |
| Создать воздушную цель | Кнопка `ЗАСПАВНИТЬ РАНДОМНУЮ ЦЕЛЬ` |
| Создать залп баллистических целей | Кнопка `ЗАЛП MLRS HIMARS` |

Назначение `+` и `-` зависит от активного экрана:

- на командирском экране меняется дальность радара с шагом 5 км в пределах 5–50 км;
- на операторском экране меняется ручной оптический зум в пределах `1x–60x`.

Базовый сценарий симуляции:

1. Включить главное питание.
2. Включить обзорную РЛС.
3. Создать случайную цель или баллистический залп.
4. Дождаться появления устойчивой трассы в таблице командирского экрана.
5. Выбрать трассу щелчком по её строке — секторное сопровождение включится автоматически.
6. Переключиться на операторский экран клавишей `C`.
7. Выбрать `ЗУР` или `ПШК` и открыть огонь клавишей `Space`.

Для пуска ракеты должны одновременно выполняться условия: включено питание, выбрана и сопровождается трасса, цель находится в секторе наведения, прошёл двухсекундный cooldown и свободен хотя бы один из четырёх каналов наведения.

## Архитектура

```text
цели в группе radar_targets
        ↓
RadarScanner — видимость и дальность обнаружения
        ↓
GlobalPantsirSystem.targets — текущие наблюдения
        ↓
обзорная/секторная РЛС — формирование и устаревание трасс
        ↓
GlobalPantsirSystem.tracks
        ↓
командирский экран → выбор цели → наведение башни и оптики
        ↓
операторский экран → пуск ракеты или огонь из пушек
```

`GlobalPantsirSystem` подключён как autoload и хранит всё общее состояние симуляции: питание, состояние радаров, цели и трассы, выбранную цель, положение приводов, боекомплект, cooldown и каналы наведения. При изменении логики важно учитывать, что его состояние сохраняется при смене сцен, пока не перезапущено дерево проекта.

Каждый пакет `RadarScanner` содержит время фактического измерения. Трасса хранится на этом времени, а оптика, пусковая, индикаторы и ракетные каналы получают её единый прогноз на текущий физический тик через `GlobalPantsirSystem.get_predicted_track_state()`. Это исключает скрытую задержку одного 50-мс радарного пакета и расхождение координат между потребителями.

## Ключевые параметры симуляции

Все расстояния используются как условные метры.

| Параметр | Текущее значение | Где менять |
|---|---:|---|
| Начальная дальность отображения | 30 000 | `GlobalPantsirSystem.MAX_RANGE` |
| Скорость обзорной РЛС | 30 об/мин, 2 луча (СМ) / 60 об/мин, 1 луч (С1) | `SCAN_SPEED_RPM`, `SOC_SINGLE_BEAM_SCAN_SPEED_RPM` |
| Ширина луча обзорной РЛС | 6° | `BEAM_WIDTH_RAD` |
| Допустимое отклонение секторного сопровождения | ±45° | `SECTOR_WIDTH_RAD` |
| Время жизни трассы без обновления | 5 с (у С1 — не меньше 2,5 циклов обзора) | `TRACK_DECAY_TIME` |
| Боекомплект пушек | 1200 | `ammo_guns` |
| Начальная скорость снаряда | 960 | `GUN_MUZZLE_VELOCITY` |
| Интервал между выстрелами | 0,024 с | `GUN_RATE_OF_FIRE` |
| Боекомплект ракет | 12, по 3 в каждой из 4 рук | `missile_tubes_loaded` / `ammo_missiles` |
| Подготовка руки перед выходом ракеты | 1 с | `MISSILE_ARM_RAISE_TIME` |
| Интервал между пусками ракет | 2 с | `MISSILE_COOLDOWN_TIME` |
| Каналы наведения ракет | 4 | `guidance_channels` |
| Максимальная скорость ракеты | 1300 м/с (95Я6) / 1700 м/с (95Я6М) / 820 м/с (ТКБ-1055) | `MissileFlightConfig.maximum_speed_mps` |
| Максимальная дальность ракеты | 20 000 м (95Я6) / 40 000 м (95Я6М) / 7000 м (ТКБ-1055) | `MissileFlightConfig.maximum_distance_m` |
| Время жизни ракеты | 30 с (95Я6) / 35 с (95Я6М) / 13,5 с (ТКБ-1055) | `MissileFlightConfig.maximum_flight_time_s` |
| Время перезарядки | 30 с | `RELOAD_TIME_S` |

## Как добавить новый тип цели

Новая цель должна:

1. Наследоваться от `Node3D`/`CharacterBody3D` и иметь `global_position` и `velocity`.
2. При входе в дерево получить уникальный идентификатор:

   ```gdscript
   radar_id = GlobalPantsirSystem.get_new_uid()
   ```

3. Войти в группу обнаруживаемых целей:

   ```gdscript
   add_to_group("radar_targets")
   ```

4. Предоставлять поля `radar_id` и `critical_hit`. Необязательное поле `radar_detection_range` переопределяет стандартную дальность обнаружения 30 км.
5. Реализовать `take_damage(is_critical: bool)`, если цель должна получать урон.
6. Получить отдельную `.tscn`-сцену и быть подключённой к нужному генератору в `GlobalPantsirSystem.gd`.

Существующие `Drone_Lutiy.gd`, `tomahawk.gd` и `BallisticTarget.gd` можно использовать как шаблоны.

## Сборка

Профили экспорта уже находятся в `export_presets.cfg`.

Linux:

```bash
godot --headless --path . --export-release "Linux" build/linux/PantsirSim.x86_64
```

Windows:

```powershell
godot --headless --path . --export-release "Windows Desktop" build/windows/PantsirSim.exe
```

Каталог `build/` в Git не хранится.

### Автосборка и релизы

Workflow `.github/workflows/build.yml` на каждый push в `main` и pull request ставит Godot 4.7.2 с шаблонами экспорта, импортирует проект, прогоняет `Tests/MissilePhysicsTest.tscn` и собирает Windows и Linux. Сборки доступны как artifacts запуска.

Релиз выпускается тегом версии:

```bash
git tag v1.1.0
git push origin v1.1.0
```

Workflow соберёт архивы `PantsirSim-<версия>-windows.zip` и `PantsirSim-<версия>-linux.zip` и опубликует их в GitHub Release. Перед тегом обновите `config/version` в `project.godot` и версии в `export_presets.cfg`.

## Проверка изменений

Headless-набор `Tests/MissilePhysicsTest.tscn` проверяет 6DOF-отклик, профиль скорости и дальности, независимость от render FPS, ограничения перегрузки, взрыватель, наведение и фильтрацию измерений. Запуск:

```powershell
godot --headless --path . Tests/MissilePhysicsTest.tscn
```

Дополнительно нужна ручная проверка после изменения логики:

1. Проект открывается без ошибок импорта и парсинга GDScript.
2. Главное питание включает оба экрана.
3. Обзорная РЛС обнаруживает случайную цель.
4. Выбранная трасса сопровождается и видна в оптическом канале.
5. Пушка и ракета уменьшают соответствующий боекомплект.
6. Поражённая цель переходит в состояние повреждения или удаляется после взрыва.
7. Залп создаёт шесть целей с интервалом две секунды.
8. Linux/Windows экспорт запускается отдельно от редактора.

Для автоматической проверки загрузки проекта после установки Godot можно использовать:

```bash
godot --headless --path . --editor --quit
```

## Известные ограничения и технический долг

- физика работает с частотой 200 тиков/с, что может заметно нагружать слабые системы;
- состояния интерфейса и симуляции тесно связаны через глобальный autoload;
- UI в основном рисуется вручную в `_draw()`, поэтому изменение компоновки требует правок координат в коде;
- столкновения снарядов проверяются перебором всех целей, без пространственного индекса;
- происхождение части сторонних моделей и изображений пока не описано (источники фото комплексов — `Assets/Complexes/CREDITS.md`).

## Рекомендации по дальнейшей разработке

- разделить глобальную логику на подсистемы радара, сопровождения, вооружения и сценариев;
- перенести балансные значения в Godot `Resource`, чтобы менять их без редактирования кода;
- заменить ручные координаты интерфейса на `Container`-узлы и добавить адаптацию к разрешению;
- добавить отдельную тестовую сцену для целей и вооружения;
- описать происхождение и лицензии всех внешних ассетов.

## Политика ИИ

Изначально проект делался вручную. Затем поверх готовой базы ИИ проделал громадную работу по её приведению в играбельный вид.

Предлагать улучшения и присылать pull request'ы, сделанные с помощью ИИ, можно — но только если вы здраво понимаете, что и как добавляете, и представляете разницу между вайбкодингом и использованием ИИ для написания кода.
